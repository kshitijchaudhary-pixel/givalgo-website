# bbcon lucky draw

Visitors at the bbcon demo station scan a QR code and land on a short
Givalgo-branded form asking for full name, work email and organization. That
enters them in a draw for **two winners**. **Each** winner gets a **$50 Uber
Eats gift card** and **12 months of Discover Pro**. Every entry lands in a
Google Sheet so we can follow up.

| File | What it is |
|---|---|
| `bbcon/index.html` | The entry form, which is where the QR code points: **givalgo.ai/bbcon** |
| `bbcon/booth/index.html` | The booth display. Open it with the booth link from the sheet, full screen on the station monitor. |
| `bbcon/booth/qrcode.js` | [qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) 1.4.4 (MIT), unmodified. It draws the booth QR code. |
| `build/bbcon/leads.gs` | Google Apps Script. It stores entries, checks the entry key, and adds the **bbcon** menu to the sheet. |
| `build/bbcon/make_qr.py` | Makes a printable QR code (SVG/PNG) for a given key, into the git-ignored `build/bbcon/out/`. |

```
booth screen ── QR: givalgo.ai/bbcon/#<key> ──▶ form ──POST (+key)──▶ Apps Script ──▶ Google Sheet
                                                                       refuses a missing or old key
```

These pages are hand-written, not generated by `build/build.py`, and they're
`noindex` and left out of `sitemap.xml`. They go live like the rest of the site:
merge to `main` and GitHub Pages serves them.

## Only people who scanned the QR code can enter

The QR code carries an **entry key**: `givalgo.ai/bbcon/#<key>`.

- **Typing or sharing `givalgo.ai/bbcon`** shows "Scan the code at our booth to
  enter" instead of the form.
- **The sheet checks the key on every entry**, so a made-up key or a stale link
  is refused even by someone who bypasses the page.
- **The form removes the key from the address bar** as soon as it loads, so
  copying or sharing the link from the phone doesn't pass the key along.
- **The key is never in this repo** (it's public). It lives in the Apps Script's
  properties and in the booth link, after the `#`. That part of a URL is never
  sent to any server, so the public `givalgo.ai/bbcon/booth` page has nothing to
  scan without it.

**What this can't stop:** a QR code is a link. Someone who scans it at the booth
could forward the full link before the form removes the key, or photograph the
screen. If a link gets out, use **bbcon → Open entries / new booth link**. That
makes a new key and the old one stops working immediately. You could also do it
at the start of each day. Each email still gets only one chance in the draw.

## Setting up the sheet (one time, about 10 minutes)

1. **Create the sheet.** In Google Drive, create a spreadsheet called *bbcon
   leads* and share it with whoever does the follow-up.
2. **Add the script.** In the sheet, open **Extensions → Apps Script**, replace
   the stub with all of `build/bbcon/leads.gs`, and save.
3. **Deploy it as a web app.** Click **Deploy → New deployment**, choose the
   type **Web app**, and set:
   - *Execute as:* **Me**
   - *Who has access:* **Anyone**. Phones at the booth aren't signed in to our
     Google account. If Workspace only offers "Anyone within …", an admin has
     to allow public web apps, or you can deploy from a personal account.

   Click **Deploy**, authorize when asked, and copy the **Web app URL**. It
   ends in `/exec`.
4. **Connect the form.** In `bbcon/index.html`, set
   `const LEADS_ENDPOINT = "https://script.google.com/macros/s/…/exec";`,
   then commit and merge.
5. **Open entries.** Reload the sheet so the **bbcon** menu appears, then choose
   **bbcon → Open entries / new booth link**. It shows a link like
   `https://givalgo.ai/bbcon/booth/#1a2b3c4d`. That link is the booth screen,
   so bookmark it on the booth laptop and only share it with booth staff.
   Opening the `/exec` URL in a browser now shows `"entries_open":true`.
6. **Test for real.** Open the booth link, scan the code with your phone, submit,
   and check the row appears on the **Leads** tab. Then type `givalgo.ai/bbcon`
   into your phone and check that it sends you to the booth instead.
   Entries from `@givalgo.ai` addresses can never win, so the team can test
   freely. Delete any test rows made from personal addresses.

> If you change `leads.gs` later, go to **Deploy → Manage deployments → Edit →
> Version: New version**. That keeps the same `/exec` URL. A brand-new
> deployment gets a new URL, and you'd have to repeat step 4. Redeploying keeps
> the entry key.

## At the booth

- Open the booth link (**bbcon → Show booth link**) on the station screen and go
  full screen (F11 on Windows, ⌃⌘F in Chrome on a Mac). The layout fills a
  landscape monitor or a portrait tablet or monitor.
- **Offline fallback:** copy `bbcon/booth/index.html` and `qrcode.js` to the
  laptop, then open the file with `#<key>` on the end of its address. Visitors
  submit using their own phone data.
- Visitors can also enter on a shared iPad. Tap the QR code on a touchscreen,
  or open the form's link on the iPad. After each entry, **Enter someone else**
  clears the form for the next person.
- **Printed QR code (banners, table tents):**
  `python3 build/bbcon/make_qr.py <key>` (needs `pip install segno pillow
  opencv-python-headless`). It writes `build/bbcon/out/qr.svg` and `qr.png`.
  Don't commit them. A print stops working if you open entries again with a
  new key.

## The **bbcon** menu

| Item | What it does |
|---|---|
| Open entries / new booth link | Makes a new entry key and shows the booth link. Any older QR code, on screen or printed, stops working. It asks first if entries are already open. |
| Show booth link | Shows the current link again. |
| Close entries | Refuses every entry. The form tells visitors the draw isn't taking entries. |
| Draw 2 winners | Picks two different people at random. Each email gets one chance however many times it was submitted, and `@givalgo.ai` addresses are never eligible. It asks first if winners were already drawn. |
| Draw 1 replacement winner | For a winner who doesn't reply within the 14 days in the rules. It never picks anyone already drawn. |

The **Leads** tab has one row per submission: *Submitted at, Full name, Email,
Organization, Source, Repeat entry*. When an email submits again, the new row
is kept (it may correct a name or organization) and marked **yes**. Every pick
goes on the **Draw log** tab: when, who ran it, which draw, how many people were
eligible, and the winner's name, email and organization.

**After bbcon:** choose **Close entries**, then **Draw 2 winners**.

## Changing things

- **Adding a question:** add a `<div class="field">` to `bbcon/index.html`,
  add its check to `fields`, and add it to the `URLSearchParams` body. In
  `leads.gs`, add a column at the end of `HEADERS` and the value to
  `appendRow`. Then deploy a new version of the script (see the note above).
- **Rules and copy:** the official rules are at the bottom of
  `bbcon/index.html`, under **Official rules**. The 14-day reply window, the
  18+ age limit and the exclusion of employees are defaults, not decisions
  anyone has made yet, so have the rules reviewed before the event.
