# bbcon lucky draw

Visitors at the bbcon demo station scan a QR code and land on a short
Givalgo-branded form asking for full name, work email and organization. That
enters them in a draw for **two winners**. **Each** winner gets a **$50 Uber
Eats gift card** and **12 months of Discover Pro**. Every entry lands in a
Google Sheet so we can follow up.

| File | What it is |
|---|---|
| `bbcon/index.html` | The entry form, which is where the QR code points: **givalgo.ai/bbcon** |
| `bbcon/booth/index.html` | The booth display, **givalgo.ai/bbcon/booth**. Run it full screen on the station monitor. |
| `bbcon/qr.svg` / `qr.png` | The QR code on its own, for print (SVG) and slides (PNG). |
| `build/bbcon/leads.gs` | Google Apps Script that writes entries to the sheet and adds the draw menu. |
| `build/bbcon/make_qr.py` | Regenerates the QR outputs if the form URL changes. |

```
phone ──scan──▶ givalgo.ai/bbcon ──POST──▶ Apps Script web app ──▶ Google Sheet "Leads" tab
```

These pages are hand-written, not generated by `build/build.py`, and they're
`noindex` and left out of `sitemap.xml`. They go live the same way as the
rest of the site: merge to `main` and GitHub Pages serves them.

## Connecting the Google Sheet (one time, about 10 minutes)

Until this is done, the form shows "This form isn't connected yet" instead of
accepting entries it can't save.

1. **Create the sheet.** In Google Drive, create a spreadsheet called *bbcon
   leads* and share it with whoever does the follow-up.
2. **Add the script.** In the sheet, open **Extensions → Apps Script**, replace
   the stub with all of `build/bbcon/leads.gs`, and save.
3. **Deploy it as a web app.** Click **Deploy → New deployment**, choose the
   type **Web app**, and set:
   - *Execute as:* **Me**
   - *Who has access:* **Anyone**. Phones at the booth aren't signed in to our
     Google account. If Workspace only offers "Anyone within …", an admin has
     to allow public web apps, or you can deploy from a personal account.

   Click **Deploy**, authorize when asked, and copy the **Web app URL**. It
   ends in `/exec`.
4. **Check it.** Open that URL in a browser. You should see
   `{"ok":true,"service":"bbcon-leads"}`.
5. **Connect the form.** In `bbcon/index.html`, set
   `const LEADS_ENDPOINT = "https://script.google.com/macros/s/…/exec";`,
   then commit and merge.
6. **Test for real.** Scan the QR code on givalgo.ai/bbcon/booth with your phone,
   submit, and check the row appears on the **Leads** tab. Entries from
   `@givalgo.ai` addresses can never win, so the team can test freely. Delete
   any test rows made from personal addresses.

> If you change `leads.gs` later, go to **Deploy → Manage deployments → Edit →
> Version: New version**. That keeps the same `/exec` URL. A brand-new
> deployment gets a new URL, and you'd have to repeat step 5.

## At the booth

- Open **givalgo.ai/bbcon/booth** on the station screen and go full screen (F11 on
  Windows, ⌃⌘F in Chrome on a Mac). The layout fills a landscape monitor or a
  portrait tablet or monitor.
- **Offline fallback:** the booth page is a single self-contained file. If the venue
  Wi-Fi is down, open `bbcon/booth/index.html` straight from a laptop. Visitors
  submit using their own phone data.
- Visitors can also enter on a shared iPad. After each entry, **Enter someone
  else** clears the form for the next person.

## The sheet and the draw

The **Leads** tab has one row per submission: *Submitted at, Full name, Email,
Organization, Source, Repeat entry*. When an email submits again, the new row
is kept (it may correct a name or organization) and marked **yes**.

After bbcon, reload the sheet so the **bbcon** menu appears:

- **Draw 2 winners** picks two different people at random. Each email gets one
  chance however many times it was submitted, and `@givalgo.ai` addresses are
  never eligible. If winners have already been drawn, it asks before drawing
  again.
- **Draw 1 replacement winner** is for a winner who doesn't reply within the
  14 days in the rules. It never picks anyone who has already been drawn.

Every pick is written to the **Draw log** tab: when, who ran it, which draw,
how many people were eligible, and the winner's name, email and organization.

## Changing things

- **Adding a question:** add a `<div class="field">` to `bbcon/index.html`,
  add its check to `fields`, and add it to the `URLSearchParams` body. In
  `leads.gs`, add a column at the end of `HEADERS` and the value to
  `appendRow`. Then deploy a new version of the script (see the note above).
- **Rules and copy:** the official rules are at the bottom of
  `bbcon/index.html`, under **Official rules**. The 14-day reply window, the
  18+ age limit and the exclusion of employees are defaults, not decisions
  anyone has made yet, so have the rules reviewed before the event.
- **Moving the form:**
  ```bash
  pip install segno pillow opencv-python-headless
  python3 build/bbcon/make_qr.py https://givalgo.ai/new-path
  ```
  This rewrites the QR files and the code, link and URL on the booth page.
  Before writing anything, the script checks that its own output scans.
